## 3. Risks found

**Security**
- ✅ **RLS really enforced:** `withOrg` runs one TCP transaction with `set_config('app.org_id', …, true)` + `SET LOCAL ROLE flowstack_app`. That role is `NOLOGIN` and owns no tables, so RLS applies without FORCE. It isn't on Neon's HTTP driver. `tests/rls.test.ts` covers the cross-org read.
- 🟡 **Residual RLS risk:** any code that reads tenant tables through `adminDb()` bypasses RLS by design (queue, admin, billing). It's a convention, not enforced. `pnpm doctor` should check the app role isn't a table owner and that FORCE isn't needed.
- ✅ **Tokens encrypted** with libsodium secretbox (`lib/crypto.ts`, 32-byte key check). Default scopes are granular and read-only (`lib/env.ts` XERO_SCOPES), with no write scope. Nothing checks at start-up that an override has no write scope (doctor will).
- 🟡 **Logs:** cookie and email aren't in the redact list.

**Data correctness**
- 🟡 **Floating-point money:** money is `numeric(14,2)` read as JS numbers. Sums are float, rounded at storage and display; no drift seen yet, but SPRINT's pitfall applies. Fix only if a test shows drift.
- 🟡 **No central sign normalisation module.** Signs follow Xero's standardLayout report sections, and live and fixture cash flows reconcile.
- 🟡 **`invalid_grant` leaves the connection "active".** The user sees refresh failures, not a reconnect banner.
- 🟡 **Inline refresh:** a large ledger can exceed the 300 s function limit. Jenki took 90 s, about 125 calls, before the incremental change.

**Vercel**
- 🟡 **Mocks on Vercel:** mock mode reads `mocks/` from disk (traced in next.config); it's enabled only when NEXT_PUBLIC_API_MODE=mock or outside production.
- 🟡 **Migrations need the direct URL:** DDL must use the unpooled Neon URL. The migrate script prefers `DATABASE_URL_UNPOOLED`, which isn't documented in `.env.example`.
